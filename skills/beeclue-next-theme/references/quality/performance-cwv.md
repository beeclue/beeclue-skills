# Core Web Vitals & Next.js Performance Engineering

Every Next.js site generated by `beeclue-next-theme` is engineered to achieve 95+ PageSpeed scores and green metrics across Google Core Web Vitals.

---

## 1. Core Web Vitals Targets

| Metric | Full Name | Target Threshold | Primary Engineering Fix |
| :--- | :--- | :--- | :--- |
| **LCP** | Largest Contentful Paint | `< 1.2s` | Priority flag on hero `<Image>`, AVIF/WebP formats, zero render-blocking CSS |
| **INP** | Interaction to Next Paint | `< 200ms` | Zero heavy client-side JavaScript, pure CSS transitions, Server Components |
| **CLS** | Cumulative Layout Shift | `0.00` | Explicit aspect ratios on all media containers, `next/font` zero-CLS self-hosting |
| **FCP** | First Contentful Paint | `< 0.8s` | Server Components rendering HTML instantly from Edge regions |

---

## 2. Zero-Fat JavaScript Discipline

1. **Avoid Bloated Animation Frameworks**: Default to pure CSS keyframes, spring cubic-bezier transitions, and native `IntersectionObserver` over heavy JS animation bundles.
2. **Dynamic Imports for Heavy Modals**: Use `next/dynamic` with `ssr: false` for interactive calculators or 3D viewports below the fold:
   ```tsx
   import dynamic from "next/dynamic";
   const InteractiveCalculator = dynamic(() => import("@/components/tools/calculator"), {
     loading: () => <div className="h-64 rounded-2xl bg-neutral-100 dark:bg-neutral-800 animate-pulse" />,
   });
   ```

---

## 3. Font Optimization via `next/font`
- Fonts loaded via `next/font/google` are automatically downloaded at build time and hosted locally.
- Zero network requests to Google Fonts at runtime.
- Built-in `size-adjust` prevents layout shifts when web fonts load.
